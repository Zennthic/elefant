What Elefant Does for You

Elefant is two things in one: a team Wiki and a personal AI memory layer. Both are searchable by your AI assistant (Claude, Cursor, and others) using the open MCP standard — no vendor lock-in, no data leaving your org's infrastructure.

📖 Wiki — shared knowledge Markdown documents your team maintains: SOPs, runbooks, architecture notes, decisions. Your AI can search and read these automatically when you ask it a relevant question.
🧠 Memories — your persistent context Facts, preferences, and decisions you (or your AI) store. These persist across every session and every tool. Your AI remembers what you've told it — even weeks later.
🔒 Private by default Your memories belong to your org. Nothing is sent to Anthropic, OpenAI, or any other AI vendor. The AI reads from Elefant — it doesn't store to it behind your back.
🔌 Works everywhere Same connection works in Claude Desktop, Claude Code CLI, Cursor, and any MCP-compatible tool. One setup; it follows you across your workflow.

Accepting Your Invite & First Login

Your org admin will send you a one-time invite link. Here's what to expect when you open it:

  1. 1

    Open the invite link. It looks like: https://your-domain.com/invite/<token>

    The link is single-use and expires in 7 days. Don't forward it to anyone else.

  2. 2

    Set your password. Choose a strong, unique password. You'll be asked to confirm it.

  3. 3

    Enrol in MFA. Scan the QR code with an authenticator app (Google Authenticator, Authy, or any TOTP app). Enter the 6-digit code to confirm enrolment.

  4. 4

    You're in. You'll land on the Elefant home screen. Your Wiki and Memories tabs are ready to use.

MFA is required
Multi-factor authentication is mandatory for all users. Make sure your authenticator app is backed up (e.g., via iCloud Keychain or your password manager). If you lose access to your MFA device, contact your org admin.

On future logins, go to https://your-domain.com/login. Enter your username and password, then your MFA code.

Creating Your API Token

Your AI tools connect to Elefant using a personal API token. Think of it as a key that lets your AI assistant into your knowledge base. You create it once and paste it into your Claude config.

  1. 1

    Log in to Elefant and click your name at the top right to open My Settings.

  2. 2

    Scroll to API tokens.

  3. 3

    Click + New token. Give it a descriptive name, e.g., claude-desktop. Make sure these are on:

    • ✅ Memory read
    • ✅ Memory write (off by default; without it your assistant cannot capture)
    • ✅ Wiki read
    • ✅ Board read

    Wiki write lets the assistant write pages, but only in the AI folder. Turn on Board write if the assistant should add and move cards.

  4. 4

    Copy the token immediately. It is shown exactly once. Paste it into a password manager or directly into your Claude config (next section) right away.

Token shown once
If you lose the token before using it, delete it and create a new one. Never share your token with anyone — it grants access as you.

Connecting Claude Desktop

Claude Desktop reads MCP server configuration from a JSON file on your computer. You'll edit this file once and then Claude Desktop connects automatically every time it starts.

macOS

Open this file in any text editor (it may not exist yet — create it if needed):

~/Library/Application Support/Claude/claude_desktop_config.json

Windows

%APPDATA%\Claude\claude_desktop_config.json

Configuration to add

Paste the following into the file, replacing the two placeholder values. If the file already has content, merge the "mcpServers" key into the existing object — don't overwrite the whole file.

{
  "mcpServers": {
    "elefant": {
      "url": "https://YOUR-DOMAIN.com/mcp",
      "transport": "streamable-http",
      "headers": {
        "Authorization": "Bearer YOUR-TOKEN-HERE"
      }
    }
  }
}

Replace:

  • YOUR-DOMAIN.com → the domain your org admin gave you
  • YOUR-TOKEN-HERE → the token you created in Section 3
  1. 5
    Save the file and restart Claude Desktop completely (quit and reopen).
  2. 6
    In a new conversation, look for the 🔌 tools icon in the input bar. Click it — you should see "elefant" listed with tools like unified_search, memory_add, etc.
Verify the connection
Ask Claude: "Search my Elefant knowledge base for anything about [a topic your org has documented]." If it returns results, you're connected.
Claude Desktop version requirement
Remote MCP (Streamable HTTP) requires Claude Desktop 0.10 or later. Update if you see an error about unsupported transport.

Connecting Claude Code CLI

Claude Code (the terminal CLI) uses MCP servers defined in a .mcp.json file. You can configure Elefant globally (available in every project) or per-project.

Option A — Global config (recommended)

Run this command in your terminal, replacing the placeholders:

claude mcp add --transport streamable-http \
  --header "Authorization: Bearer YOUR-TOKEN-HERE" \
  elefant https://YOUR-DOMAIN.com/mcp

This writes to your global Claude Code MCP config and makes Elefant available in every session.

Option B — Project config (.mcp.json)

In your project root, create or edit .mcp.json:

{
  "mcpServers": {
    "elefant": {
      "url": "https://YOUR-DOMAIN.com/mcp",
      "transport": "streamable-http",
      "headers": {
        "Authorization": "Bearer YOUR-TOKEN-HERE"
      }
    }
  }
}
Don't commit your token
If using per-project .mcp.json, add it to .gitignore. Your token is a credential — treat it like a password.

Verify in Claude Code

Start a session and run:

/mcp

You should see elefant listed as a connected server. From then on, Claude Code will automatically call Elefant tools when relevant.

Connecting via OAuth (Claude.ai web & mobile)

For the Claude.ai web app and the Claude mobile app (including on iPad), Elefant supports OAuth-based MCP Connectors. This is the recommended approach for mobile: no token to paste, no config file — just a URL and a login.

Adding the MCP Connector

  1. 1

    Open Claude.ai → Settings → Connectors (or MCP Servers, depending on your version).

  2. 2

    Click Add Connector and enter the URL:
    https://YOUR-DOMAIN.com/mcp

  3. 3

    Claude.ai will redirect you to the Elefant OAuth consent screen. Log in with your Elefant username and password (plus your MFA code), then click Authorise.

  4. 4

    You're returned to Claude.ai. The connector is now active — no token required.

iPad & iPhone
On the Claude mobile app, go to Settings → Connectors and follow the same steps. This works identically to the web app. The OAuth flow opens in your browser and returns you to the app after authorisation.

Managing your OAuth sessions

To view, adjust, or revoke active OAuth sessions, log in to Elefant → Profile → OAuth sessions. Each session lists the scopes it holds (wiki read/write, memory read/write). Use Edit to add or remove a scope in place — for example, enabling wiki write you skipped at sign-in — without revoking and re-pairing the client. An edited session is tagged edited so you can tell it apart from one that still matches the consent you originally approved. Use Revoke to end a session entirely; Claude.ai will prompt you to re-authorise on next use.

Telling Your AI to Use Elefant

Once connected, Claude already knows how to use Elefant's tools — but it works much better when you give it explicit instructions to treat Elefant as its first-class memory source. Add these to your Claude settings and, if using Claude Code, your project's CLAUDE.md.

Claude Desktop — Custom System Prompt

In Claude Desktop → Settings → Custom Instructions (or "System Prompt"), add:

You have access to an Elefant knowledge base and memory store via MCP tools. MEMORY PROTOCOL: - Before answering any question that may be covered by past decisions, preferences, or prior work, call unified_search with a relevant query. - After any session where significant decisions, preferences, or facts were established, call memory_add to store them for future sessions. - When I ask you to "remember" something, always call memory_add immediately. - When I ask "what do you know about X" or "have we discussed X", call unified_search first. SEARCH STRATEGY: - Use unified_search as your default — it searches both wiki and memories together. - Use wiki_search_only when I'm asking about documented procedures or reference material. - Use memory_search when I'm asking about personal preferences, past decisions, or stored facts. TAG CONVENTION for memory_add: - Add relevant topic tags: e.g. ["project-name", "decision", "infrastructure"] - For important decisions, add the "decision" tag. - For preferences and config, add "preference". - For how-to procedures, add "procedure".

Claude Code CLI — CLAUDE.md

Create or edit CLAUDE.md in your project root (or ~/.claude/CLAUDE.md for a global config):

# Project: [Your Project Name] ## Memory & Knowledge Base You are connected to an Elefant knowledge base via the `elefant` MCP server. **Always search before answering** questions about this project, its history, decisions, or conventions. Use `unified_search` with a relevant query before coding or advising. **Store important facts**: after any session where significant architectural decisions, API contracts, or conventions are established, use `memory_add` to preserve them. **Memory tags to use for this project**: [your-project-slug], decision, architecture, convention, api, preference. **Search first, then code**: if a question touches existing patterns, past decisions, or team conventions — search Elefant before writing new code. ## When to search Elefant - Before suggesting an approach to a problem: check if we've solved it before - Before writing a configuration: check if the team has a standard - When the user references "what we decided" or "how we do things" - When starting a new session on this project

Claude.ai — Custom Instructions

In Claude.ai → Profile → Custom Instructions, add the same Memory Protocol block from above. This applies to all Claude.ai conversations where the Elefant connector is active.

Quick test
After adding the instructions, start a new conversation and say: "Search Elefant for anything related to [your project or team name]." Claude should call unified_search and return any matching wiki pages or memories.

Using the Wiki

The Wiki is your team's shared knowledge base — think of it as a private, AI-searchable notion or Confluence. You can read pages, create new ones, and organise content in folders.

Navigating the Wiki

  1. 1
    Go to https://your-domain.com/ and select the Wiki tab.
  2. 2
    The left panel is the File Tree — folders and pages organised by your admin. Click any folder to expand it; click a page to view it.
  3. 3
    Click Edit in the top-right of any page to start editing inline. The editor supports Markdown with a live preview.

Creating New Content

What you want to doHow
New page inside a folder Hover the folder in the tree → click the 📄 icon → enter a filename
New page at root level Hover "File Tree" header → click the 📄 icon → enter a filename
New subfolder Hover a folder → click + → enter folder name
New root folder Hover "File Tree" header → click +

Editing & Saving

  1. 1
    Click Edit on any page. The page becomes an editable Markdown textarea.
  2. 2
    Write in Markdown: # Heading, **bold**, - bullet, ```code```, etc.
  3. 3
    Click Save. Your changes are committed immediately and the page is re-indexed for AI search.
AI can find what you write
After saving, your page is automatically re-embedded and searchable by AI. Changes typically appear in AI search results within 30 seconds of saving.

Writing Tips for AI Discoverability

  • Use clear, descriptive headings — the AI searches full text, but headings anchor meaning.
  • Add tags at the top of pages (frontmatter: tags: [infrastructure, runbook]) — these filter AI results.
  • Write decisions explicitly: "We decided to use X because Y" is better than "X is used here."
  • Prefer prose over bullet-only lists for context-heavy knowledge — semantic search rewards natural language.

Using the Board

The Board is a Kanban board for work and ideas, shared by your org and by your AI assistants. A card is a title and a description in a column. Use it for the things you are not doing right now but must not forget.

Working with cards

What you want to doHow
Add a card Select the Board tab → + New card → enter a title → Add card
Move a card Drag it to another column, or to another place in the same column
Discuss a card Open it and add a comment. Comments keep what happened to a card; the description says what the work is.
Attach a file Open the card and add an attachment
Classify a card Add labels, for example bug. You can filter the board by label.
Link cards Link a card to another card as related, or say that one blocks the other
Link a wiki page Link the page to the card. A wiki link to a card shows the card's live status.
Finish a card Close it. A closed card is kept and can be reopened.
The board updates live
When another person or an AI assistant changes a card, the board in your browser shows the change without a reload.

Your AI and the board

Assistants work the board with the MCP card_* tools. When you float an idea that you are not building yet, the assistant can file it as a card. When you say "note to self", it files a card for you. To let an assistant add and move cards, turn on Board write on its API token or OAuth session.

Managing Your Memories

Memories are short, structured facts stored by you or your AI assistant. Unlike wiki pages (which are team-authored documents), memories are personal context — preferences, decisions, and things you've told your AI that should persist across sessions.

Viewing Your Memories

Go to https://your-domain.com/ → Memories tab. You'll see all memories stored for your org, in reverse chronological order. Use the search bar to find specific memories.

Memory Types

TypeUse forExample
factStable truths, preferences, configs"I prefer TypeScript strict mode in all projects."
decisionChoices made that affect future work"We decided to use PostgreSQL, not MySQL, because of JSONB support."
procedureStep-by-step how-tos"To deploy: run ./deploy.sh production, then verify at /health."
eventTime-stamped occurrences"Deployed v2.3.0 on 2025-05-10. Incident-free."
derivedAI-synthesised insights"Pattern: auth bugs cluster around session expiry edge cases."

Adding a Memory

Via Claude (recommended): Just say "Remember that [fact]" and Claude will call memory_add automatically.

Via the Elefant UI: Memories tab → Add Memory → paste the content → select a type and tags → Save.

Editing or Deleting a Memory

In the Memories tab, each memory has Edit and Delete buttons. Edit to correct outdated information; delete if it's no longer relevant. Deleted memories are permanent — there is no undo.

Tag Best Practices

  • Use consistent tags across related memories: project-name, infra, api, etc.
  • Claude uses tags to filter searches — consistent tagging makes AI retrieval much more precise.
  • Keep tag names lowercase and hyphenated: code-style not Code Style.

Backup & Export

You can export all your org's memories at any time: Settings → Memory Backup → Download. The export is a portable JSON file you own and can import elsewhere.

Getting Help

Here's where to go when something isn't working:

Common issues

ProblemSolution
Claude says it can't find the Elefant tools Check that you restarted Claude Desktop after editing the config. Run /mcp in Claude Code to verify server status.
Token rejected / 401 errors The token may have expired or been deleted. Create a new one in My Settings → API tokens and update your config.
Memories appear to be empty after restoring from backup Allow 1–2 minutes for re-embedding to complete. If still empty, contact your org admin.
Lost MFA device Contact your org admin — they can reset your MFA enrolment.
Can't log in Try clearing cookies and retrying. If the invite link has expired, ask your admin for a new one.

Contact

Reach your org admin first — they can resolve most account-level issues. For platform-level issues they can't address, your admin will escalate to the Elefant support team.

Feedback welcome
Your experience shapes the product. If something feels clunky or you hit a rough edge, please let your org admin know — even a brief description helps us improve.
